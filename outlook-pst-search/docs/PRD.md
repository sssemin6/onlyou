# 사내 Outlook 메일 검색·근거 기반 AI 질의응답
제품 요구사항 문서(PRD) v1.0 · 2026년 11월 21일 · 설계안

## 1. 해결할 문제

담당자는 몇 년 전 거래처와 나눈 결정을 기억하지만, 어떤 PST에 들어 있는지, 제목에 어떤 단어를 썼는지 기억하지 못한다. 수십 GB의 보관 메일을 Outlook에 모두 연결해도 찾는 데 오래 걸리고, 검색 결과가 많으면 회신을 차례로 읽어 최종 결정을 확인해야 한다.

**제품 목표**는 사용자가 하나의 검색창에서 품번 한 개 또는 기억나는 상황 한 문장을 입력해 관련 메일을 빠르게 찾고, AI가 제시한 결론을 원문 한 번 클릭으로 검증하게 하는 것이다. 업무 메일과 그로부터 생성한 데이터는 사내 격리 환경 안에서만 처리한다.

첫 사용자는 Windows 업무 PC에서 자신의 PST 여러 개를 검색하는 직원 한 명으로 가정한다. 사내 설치 권한, PC 사양, Outlook 버전, PST 개수와 메일·첨부 구성은 실증 단계에서 확인한다. 아래 성능 수치는 출시를 판단하기 위한 목표이며 실측 전이다.

## 2. 사용자가 보게 될 결과

다음은 동작을 설명하기 위한 가상 메일이다.

| 받은 날짜 | 제목 | 본문 중 관련 구절 |
|---|---|---|
| 4월 3일 | 한빛 / A17 출하 일정 | “4월 18일 납품으로 진행하겠습니다.” |
| 4월 9일 | RE 한빛 / A17 출하 일정 | “자재 입고가 늦어져 4월 25일로 변경 요청드립니다.” |
| 4월 10일 | RE 한빛 / A17 출하 일정 | “요청 주신 4월 25일 납품으로 최종 승인합니다.” |

**사용자 질문**　“한빛 건 자재 늦어서 밀린 거, 결국 언제로 정해졌지?”

**기대 답변**　“한빛 A17의 최종 승인 납품일은 **4월 25일**입니다.[1] 당초 일정은 4월 18일이었고[2], 자재 입고 지연으로 변경을 요청했습니다.[3]”

사용자는 [1]을 눌러 4월 10일 승인 메일의 해당 문장을 바로 본다. 인용문 주변 문맥, 발신자, 발송 시각, PST 이름과 폴더도 함께 표시한다. 4월 10일 메일을 제외한 시험에서는 “4월 25일로 변경 요청한 메일은 찾았습니다. 최종 승인은 검색된 메일에서 확인되지 않습니다.”라고 답해야 한다. 서로 다른 두 한빛 프로젝트가 똑같이 조건에 맞으면 품번과 기간을 보여 주고 어느 건인지 한 번 묻는다.

## 3. 첫 버전의 기능과 인수 조건

| 기능 | 사용자가 할 수 있는 일 | 인수 조건 |
|---|---|---|
| PST 등록과 검색 가능 범위 확인 | 여러 파일을 지정하고 Outlook을 닫은 채 검색 | 읽기 전용으로 등록한다. 파일별 마지막 색인 시각, 완료 메일 수, 대기·실패·건너뜀 수와 사유를 보여 준다. 처리된 범위는 즉시 검색할 수 있다. |
| 빠른 통합 검색 | 제목·본문·첨부명·지원 첨부 본문을 한 번에 검색하고 발신자·수신자·기간·폴더·PST로 좁히기 | 첫 화면에 관련 메일 20개와 일치 구절을 표시한다. 품번의 하이픈·숫자를 보존하고, 완전 일치를 우선한다. AI가 중단되어도 작동한다. |
| 한국어 자연어 질문 | 업체 약칭, 띄어쓰기 차이, 구어체로 질문하고 “그 뒤에 누가 승인했어?”라고 후속 질문 | 이전 질문에서 선택한 업체·기간·프로젝트를 화면에 표시한다. 관련 후보가 여럿이면 구분하고, 원 검색어와 필터를 사용자가 수정할 수 있다. |
| 근거가 있는 답변 | 합의 내용·금액·담당자·날짜와 변경 경위를 확인 | 핵심 사실마다 인용을 부여한다. 요청·제안·승인·취소를 구분한다. 최신 메일이 과거 내용을 전달한 경우 원발신 시점과 작성자를 구분한다. |
| 원문 검증 | 인용을 눌러 내부 뷰어에서 원문 또는 첨부 발췌를 확인 | 메일은 인용 위치를 강조한다. 첨부는 파일명과 PDF 페이지·엑셀 시트/셀 등 포맷에 맞는 위치를 표시한다. 출처 재확인 실패 시 이를 표시하고 다른 메시지로 대신 연결하지 않는다. |
| 백그라운드 갱신 | 색인을 일시정지하고 재시작하거나 보관 파일을 추가·교체 | 중단 지점부터 재개한다. 재등록해도 결과가 늘어나지 않는다. 변경된 파일을 반영하는 동안 마지막 정상 색인을 제공하고 그 기준 시각을 표시한다. |

**첨부 범위.** 1차 지원은 텍스트 PDF, DOCX, XLSX, TXT의 텍스트와 첨부 파일명이다. 스캔본 OCR, HWP/HWPX 본문, 암호화되어 읽을 수 없는 첨부는 초기 범위 밖이다. 검색 화면에서 누락 범위를 확인할 수 있어야 한다. 파일 형식별 비중을 먼저 집계하고, 한글 문서가 핵심 근거의 상당 부분이면 해당 형식 지원을 운영 배포 조건으로 올린다.

**후속 범위.** Outlook에서 원본 열기, AI 회신 초안, 회신 대기 알림, 받은편지함 분류는 검색·답변 검증을 통과한 뒤 검토한다. 첫 버전에는 메일 전송·수정 권한이나 Superhuman 비공개 인터페이스가 필요하지 않다.

## 4. 처리 구조와 속도 설계

1. **등록 시 한 번 읽는다.** 닫혀 있거나 일관된 사본으로 확보된 PST를 메일 단위로 읽는다. Outlook이 쓰는 중이거나 파일 상태가 바뀌면 해당 파일 작업을 보류하고 상태를 표시한다. 헤더·본문·첨부명을 먼저 색인하고, 첨부 본문과 의미 검색용 벡터는 뒤에서 채운다. 원본 본문과 인용할 수 있는 구간의 대응 관계를 보존한다.
2. **두 가지 검색을 결합한다.** 로컬 전문 검색은 업체명·품번·금액과 한국어 표현을 찾고, 로컬 의미 검색은 ‘밀린 건’과 ‘납기 변경’처럼 단어가 다른 표현을 연결한다. 두 결과를 합쳐 관련도를 다시 계산한다. 빠른 검색은 언어 모델을 기다리지 않는다. AI 질문에서도 먼저 근거 후보를 표시한다.
3. **관련 회신을 다시 확인한다.** 후보 메일의 이전·이후 회신, 첨부, 관련 후속 메일을 찾아 승인과 번복 여부를 확인한다. 동일 메시지의 사본과 회신 본문의 반복 인용은 묶되 원래 위치는 보존한다. 제목이 같다는 이유만으로 다른 프로젝트를 합치지 않는다.
4. **확인된 자료로 답한다.** 사내에서 실행되는 모델에 질문과 선정된 발췌문만 전달한다. 답변의 날짜·수치·승인 상태와 인용을 대조한다. 연결되지 않는 주장은 제거하거나 미확인으로 표시한다. 답이 없으면 확인한 범위와 가장 가까운 근거를 보여 준다.
5. **출처가 바뀌면 갱신한다.** 각 인용은 자료 버전, 메시지 식별자, 본문 구간 또는 첨부 위치를 가리킨다. 파일 교체 후에는 유효한 버전만 검색한다. 자료 등록 해제 시 해당 자료의 검색·답변·미리보기 접근을 즉시 차단하고 색인·벡터·캐시를 삭제한다.

기본 배포안은 사용자별 Windows 로컬 앱이다. PC에서 AI 응답 목표를 달성하기 어려우면 사내 승인을 받은 내부 추론 서버를 별도 검증한다. 이때도 사용자별 자료 접근 경계를 유지한다. Copilot이나 Claude Code는 개발 도구로 별도 선택할 수 있으며 제품 실행, PST 색인, 사용자 질의응답의 필수 의존성에서 제외한다. 외부 도구로 개발할 때는 합성 메일과 가상 첨부만 사용한다.

## 5. 속도·정확도 출시 기준

기준 시험은 합계 50 GB의 복수 PST, 사용자 1명, 로컬 SSD에서 진행한다. 메일 수, 추출된 첨부 텍스트량, 장비 CPU·RAM·GPU, 모델과 버전, 저장장치, 색인 크기를 함께 기록한다. 키워드와 AI는 별도로 측정한다.

| 항목 | 1차 합격 목표 | 측정 방법 |
|---|---|---|
| 일반 검색 속도 | 첫 20개 결과 P95 1초 이내 | 색인 완료·앱 예열 상태에서 서로 다른 질의 100건. 입력 확정부터 화면 표시까지 측정. 결과가 적으면 마지막 결과 표시까지 측정 |
| 첫 실행 검색 속도 | P95 3초 이내 | 앱 재실행 후 첫 검색 20회. OS 캐시 조건을 기록 |
| AI 질문 체감 속도 | 근거 후보 P95 3초, 인용을 갖춘 완성 답변 P95 20초 이내 | 고정된 대표 질문 100건, 질의당 최대 약 5문장으로 측정. 모델 로딩이 필요한 첫 질문은 별도 기록 |
| 검색 적중률 | 답이 있는 질문의 90% 이상에서 상위 5건 안에 정답 근거 포함 | 사전에 지정한 정답 메일 또는 동등한 원본 첨부와 대조 |
| 답변 정확도 | 답할 수 있는 질문의 90% 이상에서 핵심 답과 상태를 모두 맞힘 | 담당자가 기입한 정답표와 대조. 요청을 승인으로 바꾸거나 취소된 일정을 최종으로 제시하면 오답 |
| 인용 품질 | 핵심 사실 인용 누락 0건, 인용 열기 성공률 100%, 인용문이 실제 주장을 뒷받침하는 비율 95% 이상 | 날짜·수치·담당자·결정 상태를 개별 주장으로 나누어 원문과 직접 대조 |
| 근거 부족 대응 | 정답이 없는 20문항에서 확정 답변 0건 | 승인 미수신, 상충 미해결, 동명 업체 미구분 사례 포함. 근거 있는 부분 답변 또는 확인 질문 허용 |
| 색인 중 사용성 | 이미 색인된 범위의 일반 검색 P95 2초 이내 | 대형 첨부 처리 중 같은 검색 시험 수행. 처리 전 항목은 화면에 대기로 표시 |

P95는 100번 중 95번이 기준 시간 안에 끝나는지를 뜻한다. 실증에서는 최초 50 GB 색인 시간, 시간당 메일 수, 최대 디스크·메모리 사용량, 사용자가 첫 검색을 할 수 있기까지의 시간도 측정한다. 원본 읽기, 텍스트 추출, 벡터 생성을 따로 기록해 병목을 구분한다. 10 GB·50 GB·100 GB 샘플의 결과를 비교하고, 확보한 데이터 범위만 실측값으로 보고한다.

## 6. 격리망과 원문 보호

- PST, 주소, 첨부, 질문, 검색어, 벡터, 답변, 인용, 로그는 지정된 PC 또는 승인된 사내 시스템에서만 처리한다. 모델과 의존성은 사내 반입 절차에 맞춘 오프라인 패키지로 설치한다. 외부 인증·모델 다운로드·원격 분석·오류 전송·클라우드 대체 호출 없이 실행해야 한다.
- 원본을 읽기 전용으로 열고 미리보기에서는 외부 이미지, 추적 URL, 매크로를 실행하지 않는다. 메일이나 첨부에 들어 있는 지시문도 검색 대상 자료로만 취급한다. 모델은 파일 전송·메일 발송 기능을 갖지 않는다.
- 색인과 임시 추출물에도 원문에 준하는 사내 접근 제어와 저장 암호화 정책을 적용한다. 기본 진단 로그에는 항목 수·소요시간·오류 코드만 남긴다. 권한이 철회된 원본은 다음 검색 및 인용 열기 시점에 차단한다.
- 인수 시험에서 외부망을 차단한 채 설치·첫 실행·색인·검색·답변·오류 복구를 수행한다. 앱과 하위 프로세스의 외부 연결 시도 0건, 타 사용자 자료 조회 0건, 고정 시험용 원본 PST의 처리 전후 해시 일치를 확인한다.

## 7. 실증 순서와 배포 판단

| 단계 | 수행 작업 | 다음 단계로 넘어가는 조건 |
|---|---|---|
| 1. 기준선 확보 | 사내 담당자가 대표 PST와 평소 찾기 어려웠던 질문 10개를 선정한다. 기존 Outlook에서 정답을 여는 시간과 성공 여부를 기록한다. | 질문별 정답 메일·첨부 위치와 확인자를 확보 |
