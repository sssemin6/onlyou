# PRD 02 · 메일과 설계 문서를 함께 찾는 사내 RAG

제품 설계안 · 2026년 11월 21일 · 사용자: Windows 업무 PC에서 설계 변경을 검토하는 설계자 및 검토자
기준 버전 `sssemin6/onlyou@de8cadf` · [1차 메일 검색 PRD](PRD.md)

## 1. 제품 결정

설계자는 한 검색창에서 PST와 업무 폴더를 조회한다. “A17 브래킷 두께가 왜 바뀌었고, 양산에도 적용됐나?”라고 물으면 **결정 내용, 이유, 적용 대상, 확인되지 않은 사항**을 각각 확인한다. 결론 옆 인용을 누르면 승인 메일의 문장, 시험 보고서의 페이지, 기준서의 절, BOM의 셀로 이동한다. 답변 시점을 지정하면 당시 유효했던 근거로 다시 조회한다.

첫 배포는 개인별 읽기 전용 색인, 로컬·허용된 사내 공유 폴더, 기존에 운영 중인 사내 생성 AI API를 사용한다. 제목·품번 검색은 생성 서버와 독립적으로 작동한다. 독립 문서 등록과 셀 단위 근거를 먼저 출시하고, OCR·시각 검색·설계 결정 저장은 품질 검증을 거쳐 추가한다. 원본 수정, CAD 모델 치수 추론, 도면 자동 승인, 팀 전체 중앙 색인은 후속 과제다.

## 2. 현재 최고 성능에서 무엇을 채택할 것인가

조사일 기준 공개 결과를 **페이지 검색 → 여러 문서로 답변 → 표 계산** 순으로 비교했다. 각 평가는 데이터와 채점 단위가 다르다. 아래 순위의 적용 범위는 해당 공개 시험이다.

**선택안.** 첫 버전은 기존 키워드·의미 검색에 문서 구조, 버전, 출처를 더한다. 같은 사내 생성 모델로 재정렬기를 켜고 끈 결과를 비교한다. 페이지 이미지 검색은 스캔·복잡한 표에서 추가 이득이 입증될 때 배포한다. 전사 지식 그래프를 미리 구축하는 비용은 보류하고, 검증 가능한 품번·문서번호·Rev.·회신 관계부터 연결한다.

## 4. 사용자 흐름과 파일별 인수 조건

1. **자료 등록**에서 기존 PST, 개별 문서 또는 로컬·사내 공유 폴더를 선택한다. 하위 폴더 포함 여부와 제외 경로를 설정한다. 읽지 못한 파일은 형식·경로별 사유와 재시도 동작을 표시한다.
2. 검색창에서 품번, 자연어, 프로젝트·문서 종류·Rev.·기간을 조합한다. 결과에는 일치한 문장 또는 표 행, 자료 종류, 발송일 또는 문서 개정일, 출처를 표시한다. 메일 첨부와 폴더 사본이 같으면 양쪽 출처를 펼쳐 볼 수 있다.
3. **설계 이력 질문**에서는 프로젝트와 답변에 사용할 PST, 문서 폴더 또는 개별 자료를 선택한다. 질문창에 선택 범위를 표시하고 후속 질문에도 적용한다. 인용을 누르면 내부 뷰어에서 해당 위치와 앞뒤 문맥을 보여 준다. 답변에는 근거별 날짜·버전과 함께 폴더 오프라인, 부분 처리, 미확인 승인을 표시한다.

|---|---|---|

## 5. 검색·계산·답변 설계

**검색.** 품번·도면번호·개정 기호의 원형을 보존하고 한글 표현 차이는 의미 검색으로 보완한다. 자료 접근 범위와 프로젝트 필터를 먼저 적용한다. 키워드·벡터 순위를 결합한 뒤 상위 후보만 재정렬한다. 문단이 적중하면 앞뒤 문단, 표 셀이 적중하면 머리글·단위·같은 행, 승인 회신이 적중하면 해당 제안과 후속 번복을 불러온다. 문서 간 연결에는 동일 프로젝트와 품번 또는 근거 안의 명시적 참조가 필요하다. 연결이 모호하면 후보를 보여준다.

**설계 이력 질문과 추가 검색.** 질문을 변경 이유, 승인 여부와 적용 범위, 도면·BOM 반영 여부처럼 확인할 항목으로 나눈다. 최초 검색 결과에서 항목별 근거를 확인한다. 필요한 근거가 빠졌거나 출처가 상충하면 추가 검색을 한 번 실행한다. 품번·문서번호·Rev.·발송일을 사용해 시험 보고서, 승인·철회 회신, 정식 도면·BOM 등 빠진 항목에 맞는 자료를 찾는다. 두 검색 모두 사용자가 선택한 자료와 현재 열람 권한을 적용한다. 다른 프로젝트나 제외한 자료가 필요하면 범위 변경을 제안하고, 사용자가 바꾼 뒤에 조회한다. 추가 검색 후에도 확인되지 않은 항목은 해당 범위에서 ‘미확인’으로 표시한다.

**근거 예산.** 일반 검색은 기존 경로를 유지한다. 사내 API 설정에 ‘설계 이력’ 프로필을 추가하고, 사용자에게 현재 주소·모델·근거 예산을 표시한다. 허용된 내부 주소에서만 4,000자와 12,000자를 같은 질문으로 비교한다. 토큰 수는 모델 토크나이저 또는 게이트웨이 한도를 기준으로 계산하고 출력·지시문 여유를 확보한다. 동일 회신의 반복 인용은 접고, 날짜가 다른 승인·반려·예외에는 예산을 배분한다. 서버 한도 초과 시 중복과 낮은 순위부터 제거하고 제외 범위를 표시한다. 구현 시 기존 API 전송 규칙과 테스트에 내부 프로필의 조건을 명시한다.

**수치 답변.** 합계·차이·최댓값 등 허용된 연산은 지정된 행과 열의 저장값으로 계산한다. 숫자·단위·대상 Rev.와 입력 셀을 답변에 붙인다. 예를 들어 변위 측정값 0.18 mm와 허용값 0.20 mm의 차이는 0.02 mm이며 두 값의 위치를 각각 인용한다. 숨김 행 포함 여부, 단위 변환 규칙, 누락값 때문에 결과가 달라지면 계산 조건을 표시하고 모호한 경우 확인을 요청한다. 원본 수식·매크로·외부 링크는 실행하지 않는다.

**결정 이력.** 제안, 시험, 조건부 승인, 정식 승인, 기준서 반영, 대체·철회 상태를 구분한다. 파일 수정일, 메일 발송일, 승인일, 발효일을 각각 저장한다. 특정 날짜에 유효한 Rev.와 적용 모델을 확인할 수 없으면 확인된 사실까지만 제시한다. 근거 없는 결론은 ‘확인 불가’, 두 출처가 충돌하면 ‘상충’과 양쪽 인용을 표시한다. 설계자가 검토한 기록에 한해 결정 이력으로 저장하며, 근거 버전이 바뀌면 재검토 대상으로 표시한다.

**주장별 원문 검증.** 답변을 개별 주장으로 나누고 각각 원문 인용을 연결한다. 인용문이 원문에 있는지 확인한 뒤, 인용과 주변 문맥이 주장에 나온 품번·수치·단위·Rev.·적용 모델·승인 상태를 뒷받침하는지 검사한다. 수치 계산은 인용된 입력값과 연산 결과를 대조한다. 예를 들어 ‘시제품만 4T 적용 승인’은 시제품 범위의 근거로 사용한다. 양산 승인에는 양산 범위를 명시한 근거가 필요하다. 일부만 검증되면 확인된 주장과 미확인 항목을 함께 표시한다.

**가상 인수 시나리오.** A17의 시험 보고서 12쪽은 변형 발생, 5월 3일 회신은 시제품만 4T 승인, 양산 BOM Rev.C의 F18은 3T, 5월 10일 Word 개정 초안은 전 모델 4T를 제안한다. 기대 답변은 “시제품 4T는 5월 3일 승인됐고 양산 BOM Rev.C는 3T입니다. 전 모델 변경은 초안이며 양산 승인 근거는 확인되지 않습니다.”이다. 근거 네 곳을 열 수 있어야 한다. 같은 자료에 후속 양산 승인 메일만 추가하면 승인 사실은 바뀌지만 BOM 반영 상태는 계속 별도로 표시한다.

## 6. 대용량·권한·원문 추적

- 파일·버전·출처·인용 위치를 분리한다. 인용 키는 자료 ID, 버전 해시, 형식별 위치, 인용 텍스트 지문으로 구성한다. SQLite 행 번호는 재색인 뒤 유지되는 영구 링크로 쓰지 않는다.
- 경로·크기·수정 시각으로 변경 후보를 찾고, 내용 해시로 동일 파일을 판정한다. 수정 중인 파일은 안정된 시점에 재시도한다. 새 버전은 백그라운드에서 작성하고 성공 시 교체한다. 삭제·이동·동명이본·암호·부분 추출·NAS 일시 단절을 구분해 표시한다. 중단 후 페이지·시트 체크포인트에서 재개한다.
- 사용자별 로컬 색인에 대해 문서 접근을 검색 직전, AI 전송 직전, 인용 열기 시점에 확인한다. 권한 철회·검증 불가 시 해당 경로의 미리보기와 AI 근거를 차단한다. 여러 사본은 열람 가능한 경로만 노출한다. 등록 해제 시 관련 색인·벡터·임시 변환본·저장된 답변 캐시를 정리한다.
- 사내 API가 중단되면 검색·원문 열람을 제공하고 생성 실패를 표시한다. 로그에는 처리 건수·소요 시간·오류 분류를 남긴다. 원문·API 키는 로그에서 제외한다. 문서 안 지시는 검색 대상 텍스트로만 처리한다.
- PC의 무거운 작업은 취소 가능한 큐로 처리한다. OCR·이미지 인덱싱은 별도 큐와 용량 한도를 둔다. 첫 배포에서 GPU는 선택 사항이며, 직접 호스팅할 모델의 라이선스·메모리·처리량은 도입 전에 측정한다.

## 7. 검수 방법과 출시 기준

아래 수치는 제안한 목표다. 한국어 사내 자료에서 아직 실측하지 않았다. 완료 프로젝트 1개와 답을 아는 설계 변경 10건으로 먼저 진행한다. 담당자가 정답과 유효 Rev., 허용 가능한 대체 인용을 작성한다. 이후 튜닝용 프로젝트와 출시 평가용 프로젝트를 분리한다.

**NotebookLM 비교.** 반출 가능한 공개·합성 자료로 같은 10개 설계 질문과 정답표를 만든다. 두 시스템에 동일한 자료와 질문을 주고 각각 새 대화에서 실행한다. 담당자가 결론·변경 이유·적용 범위·인용 적합성을 항목별로 채점하고, 근거가 없는 항목을 확정했는지와 응답 시간을 기록한다. 이 결과는 파일럿의 비교 기준으로 사용한다. 실제 사내 프로젝트는 내부에서 같은 기준으로 평가한다. 비교 기준에는 사용자가 답변에 사용할 자료를 선택하고 인용을 눌러 원문 문맥을 확인할 수 있는지도 포함한다. | 자료 범위·추가 검색 | 첫 검색에서 시제품 승인만 찾는 사례에서 후속 양산 승인 회신과 BOM을 추가로 조회한다. 같은 품번의 타 프로젝트, 사용자가 제외한 자료, 권한이 철회된 파일은 두 검색과 인용에서 모두 제외한다. 양산 근거를 제거한 사례에서는 양산 승인만 미확인으로 표시한다. |

**선정 실험.** 동일한 자료·생성 모델·질문에서 A(기존 추출·검색), B(구조 보존+주변 문맥), C(B+재정렬), D(C+해당 PDF만 시각 검색)를 비교한다. 사내 API 근거 4,000자·12,000자 비교는 B에서 다른 조건을 고정해 별도로 수행한다. 설계 이력 질문에서는 자료 범위와 근거 예산을 고정해 추가 검색을 적용했을 때 새로 찾은 필수 근거, 최종 정답, 응답 시간의 변화를 측정한다. 기초 검색 적중률, 최종 정답, 인용, 지연, 토큰량을 함께 기록한다. 채택 기준은 필수 품질·지연 목표 통과이며 동률이면 운용 부담이 낮은 구성을 선택한다.

## 8. 개발 순서와 완료 조건

| 단계 | 공동 개발 범위 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 1 · 독립 문서 검색 | 공통 추출기와 파일 등록, 안정된 출처 ID, PDF·XLSX·DOCX·구형 DOC/XLS 테스트 자료, GUI 원문 이동 | 네트워크 없이 샘플 폴더를 색인하고 지정 구절·셀·절을 연다. 기존 PST 검색이 통과한다. |

| 3 · 스캔과 지식 재사용 | 한국어 OCR, 선택적 시각 검색, 검토된 설계 결정 저장, 문서 변경 시 재검토 | 스캔 표에서의 추가 정답과 처리 비용을 제출한다. 근거가 변경된 결정에서 재검토 표시를 확인한다. |

공동 개발 착수 시 설계 담당자는 대표 프로젝트와 판정 기준, IT 담당자는 사내 API의 모델명·컨텍스트 한도·허용 경로, 개발자는 구형 Office·스캔 비율과 기준 PC 사양을 확인한다. 이 값으로 시험 조건과 우선순위를 갱신한다.
